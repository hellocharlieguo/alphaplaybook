Cascade — the whole algorithm

S1    = 100 × timing × quality
raw   = (100 − floor_score) × timing × quality  floor_score = 45
S5    = DMA base − stretch penalty  no RSI
mult  = entry_band(S5)
score = raw × mult
weight = trend_wt × score / Σ(score in trend)

Both S1 inputs are discrete ladders — no free-form numbers. A name below floor_score scores zero and drops out. If it is the only name in its trend, the trend collapses — this is what ETHA's monetary severity of 40 did before it was re-set.

Same five rungs as timing. Accelerating gaps — 0.08, 0.12, 0.08, 0.12 — so the bottom of each ladder costs more than the top. 0.60 is a floor: fade, never zero.

A monopoly and a whole-theme basket both score high for opposite reasons. That is the breadth term the old severity scale never had — and why SOXX no longer needs a hand-set floor.

Trend fill

Entry quality is the weighted mean multiplier in the trend. Below ~0.70 means every expression is stretched and redistribution has nothing good to move weight toward — the discipline is inert there.

Trend weight — how it is derived

trend_score = derivedtiming × conviction × breadth
breadth = N_eff, measured from return correlations
trend_wt = 100 × trend_score / Σ(all trend scores)

Timing is the mean of the trend's sub-themes — derived, not set, so it cannot contradict them. Conviction is the one trend-level judgment left. Not summed from its names. Summing made weight a function of how many tickers happened to be seated — adding two names to a one-name trend took it from 4.7% to 11.6% with no change in conviction at all.

Breadth is now measured rather than counted. √n assumed each sub-theme was an independent bet; the correlation matrix says the seven buildout names are worth 1.95, while two uncorrelated application names are worth 2.00.

Type in the weight box to override. The rest re-split what is left, so the book always totals 100.

Sleeve caps — standing rules

A cap spans trends, so it can hold total hard-money exposure even once silver has a second seat in AI buildout. It fires by itself when breached — set once, no weekly re-decision.

That is what separates it from a per-trend override: the override is a number you re-type each cycle, which is where version drift comes from. The cap is a rule.
